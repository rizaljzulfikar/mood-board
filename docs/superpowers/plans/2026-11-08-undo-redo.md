# Undo / Redo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Full-scope undo/redo on the mood board — 10 history entries per direction, keyboard + toolbar buttons, restores replayed to the server so they survive the 2s sync loop.

**Architecture:** Snapshot history in a pure client module (`src/lib/history.ts`): each user gesture commits a normalized snapshot of `{items, groups, connections}` into capped `past`/`future` stacks. Undo/redo swap snapshots locally and replay the normalized diff to the REST API as PATCHes (`deleted:false` = un-delete restore, `deleted:true` = re-delete, otherwise field patches) — deletes are soft server-side, so nothing is ever re-created.

**Tech Stack:** TypeScript, React 19, Next.js 15 route handlers, Mongoose, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-08-undo-redo-design.md`

## Global Constraints

- `MAX_HISTORY = 10` entries per stack; when full, drop the oldest.
- Snapshot comparisons/diffs ignore `updatedAt` and sort entities by `id`.
- Item diff fields: `x, y, width, height, z, rotation, label`. Group diff fields: `x, y, width, height, z, label`. Connection diff fields: `style` (`from`/`to` never change).
- All three PATCH routes keep existing behavior when the body has no `deleted` key.
- No new dependencies.
- Never run the full test suite (global rule); run only the files named in each task. Tests need the local MongoDB on `localhost:27030` (see `vitest.config.ts`).

## Review Focus

1. **Undo vs the sync loop:** a restored (un-deleted) entity must not be clobbered by the next sync tick — covered by route tests asserting `deletedAt` is cleared and `updatedAt` bumps (Task 2), plus plan-ops integration relying on mongoose timestamps (Task 2).
2. **In-flight label edit / drag during undo:** undo/redo must be ignored while a drag is active (`dragRef.current` non-null) — pinned by Task 3's guard step (code-reviewed; no component tests exist in this repo).
3. **No-op gestures must not consume history slots** (e.g. a click-drag that ends where it started, upload batch where every POST failed) — pinned by the `snapshotsEqual` dedupe tests in Task 1.
4. **Existing 404 semantics preserved:** a plain PATCH (no `deleted`) on a soft-deleted entity still 404s — pinned by Task 2 tests.
5. **Batch semantics:** an upload of N files is ONE undo entry — pinned by Task 3's single `commitSettled()` after the upload loop (code-reviewed via call-site list).

### Task 1: Pure history module

**Files:**
- Create: `src/lib/history.ts`
- Test: `tests/history.test.ts`

**Interfaces:**
- Consumes: types `ItemState`, `GroupState`, `ConnectionState` from `@/lib/merge` (type-only).
- Produces (used by Tasks 3–4):
  - `type Snapshot = { items: ItemState[]; groups: GroupState[]; connections: ConnectionState[] }`
  - `const MAX_HISTORY = 10`
  - `normalizeSnapshot(s: Snapshot): Snapshot` — strips `updatedAt`, sorts each array by `id`.
  - `snapshotsEqual(a: Snapshot, b: Snapshot): boolean`
  - `type HistoryStack = { past: Snapshot[]; future: Snapshot[]; settled: Snapshot }` (arrays oldest-first)
  - `initHistory(settled: Snapshot): HistoryStack` — `{ past: [], future: [], settled }`
  - `commitHistory(h: HistoryStack, next: Snapshot): HistoryStack` — if `snapshotsEqual(h.settled, next)` return `h` unchanged; else push `h.settled` onto `past` (cap 10, drop oldest), `future: []`, `settled: next`. Pure: returns a new object.
  - `undoHistory(h, current): { stack: HistoryStack; target: Snapshot } | null` — null when `past` empty; else `target` = last of `past`, `current` pushed onto `future` (cap 10, drop oldest), `settled = target`.
  - `redoHistory(h, current)` — mirror of undo with `future`/`past` swapped.
  - `type EntityKind = "item" | "group" | "connection"`, `type ServerOp = { kind: EntityKind; id: string; body: Record<string, unknown> }`
  - `planServerOps(target: Snapshot, current: Snapshot): ServerOp[]` — per kind (items, then groups, then connections): target entity missing from current → `{ deleted: false, ...allFields }`; present but differing → `{ ...onlyChangedFields }`; identical → skip; then current entities missing from target → `{ deleted: true }`. Deterministic order for tests.

- [ ] **Step 1: Write the failing tests** in `tests/history.test.ts`. Cover at minimum:
  - `normalizeSnapshot` strips `updatedAt` and sorts by `id`.
  - `commitHistory` pushes settled→past and clears future; no-op when equal ignoring `updatedAt`; caps `past` at 10 across 12 distinct commits (dropped from the front).
  - `undoHistory`/`redoHistory`: returns target + moves `current` into the opposite stack; null on empty stack; round-trip A→B→undo→A→redo→B; caps `future` at 10.
  - `planServerOps`: moved item → single op `body` `{x, y}` (only changed fields); target-only item → restore body with `deleted: false` plus all seven item fields; current-only item → `{ deleted: true }`; group label diff and connection `style` diff; identical snapshots → `[]`; snapshots differing only in `updatedAt` → `[]`.

### Task 2: `deleted` flag on the three PATCH routes

**Interfaces:**
- Consumes: nothing new (existing models/routes).
- Produces: PATCH bodies understood by `planServerOps` output (Task 3 consumes indirectly via `applyServerOps`):
  - `deleted: true` → soft-delete: doc must exist and be live (404 otherwise), set `deletedAt = new Date()`, save, return `{ item | group | connection }`.
  - `deleted: false` → un-delete: doc must exist (soft-deleted is fine, 404 only if missing), set `deletedAt = null`, then apply the other patchable fields exactly as today, save, return entity JSON.
  - No `deleted` key → today's behavior byte-for-byte (including 404 on soft-deleted docs).
  - Body parsing moves BEFORE the existence check in each route (the flag decides whether soft-deleted docs are reachable).

- [ ] **Step 1: Write the failing tests** in `tests/undo-restore.test.ts`, following the setup pattern of `tests/item-label.test.ts` (mock `@/lib/auth` `getCurrentUser`, `connectDB()`, create User + Project; helper functions that build a Request and call the route PATCH directly):
